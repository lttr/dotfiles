Key code changes

cli.ts stops owning the storage lifecycle

Open, loop, write, and close collapse into one call. The CLI now knows about SQLite in exactly one place, where it picks the implementation.

pricing.ts becomes a pure function

Pricing used to read rates from the store mid-calculation. It now takes a rate table as an argument, so it does no I/O and needs no test double.

core/mod.ts is the only place the seam is used

One function owns parse, price, and save. It accepts any Repository, so the caller decides what storage means.

Consequences

  • Storage can be swapped at one call site in cli.ts.
  • The test suite runs without touching disk.
  • price does no I/O, so it is tested with plain values.
  • core/ must not import a storage implementation directly.
  • The export path still reads store.ts and has to migrate next.
